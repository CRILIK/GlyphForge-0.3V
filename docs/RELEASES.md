# GlyphForge: обновления APK (v0.4)

## Модель обновлений

В приложении: автоматическая проверка `https://api.github.com/repos/CRILIK/GlyphForge-0.3V/releases/latest` при запуске. Если новый релиз найден, приложение показывает кнопку для открытия официальной страницы GitHub Release. Android требует ручного разрешения на установку APK. Скрытая установка невозможна без особых системных прав.

Важное ограничение: GitHub Actions `assembleDebug` генерирует **debug APK**, подпись которого может изменяться между сборками. Поэтому обновить установленный debug APK поверх предыдущего может не получиться. Не следует обещать безопасное обновление без единого постоянного ключа. Перед переходом на production APK сохраните библиотеку в .gforge через «Библиотека → Экспорт библиотеки».

## Настройка подписи, однократно

1. Сгенерируйте локальный Android release keystore (`keytool -genkeypair -v -keystore release.jks -alias glyphforge -keyalg RSA -keysize 3072 -validity 10000`). **Не добавляйте `.jks` в GitHub-репозиторий.** Сохраните защищённую резервную копию.
2. GitHub → Settings → Secrets and variables → Actions → New repository secret: `GF_KEYSTORE_B64` (base64 содержимое jks), `GF_KEYSTORE_PASSWORD`, `GF_KEY_ALIAS`, `GF_KEY_PASSWORD`.
3. Убедитесь, что `versionCode` и `versionName` в `app/build.gradle` соответствуют релизу, для следующего обновления **versionCode должен увеличиться**.
4. Создайте тег формата `v0.4.0`, push тега. Workflow `Publish signed GlyphForge release` соберёт, подпишет и выпустит APK на GitHub Releases.
5. При выпуске новой версии используйте **тот же ключ**. Иначе Android не позволит обновить существующий APK без удаления приложения и потери локальных данных.

Установленный debug APK рекомендуется не использовать как базу для непрерывных обновлений. Политика GitHub Releases позволяет проверить новую версию при запуске приложения. Проверка обновлений не передаёт личные данные и не загружает сам APK без действия пользователя.
